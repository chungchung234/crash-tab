# 종합 — 화면부수기 전체 검토

검토일 2026-11-12 · 목표는 **개인 재미 + 크롬 웹스토어 출시** 로 확정된 상태에서 심각도를 매겼다.

> **이 문서는 검토 시점의 기록이다. 고친 내용은 여기 반영하지 않는다.**
> 검토 직후 13단계가 이 목록을 받아 구현했다 — 무엇을 어떻게 고쳤고 무엇을 **버렸는지**는
> [`../specs/launch.md`](../specs/launch.md) 와 `CHANGELOG.md` 에 있다.
> 검토가 틀렸던 것, 구현하다 뒤집힌 것(요소 흔들림 증폭, 종료 요약 오버레이)도 거기 적혀 있다.

## 한 줄

**이 제품은 거의 다 만들어졌는데 아직 아무에게도 닿지 않았고, 지금 그대로 제출하면 세 가지에서 막힌다.

각 지적에 스스로 반대 심문을 한 번 돌린다, 심각도×비용으로 잘라 레인마다 7개 이하만 남긴다.

내 지적 하나("실제 페이지가 안 부서진다")는 측정을 더 해서 **범위를 좁혔다.**

## 1. 출시 블로커 — 지금 제출하면 막힌다

셋 다 비용이 작다. 합쳐서 하루 안에 끝난다.

### B1. 매니페스트 설명문이 크롬 상한 132자를 넘는다 — 업로드 자체가 실패한다

`_locales/ko/messages.json` 의 `appDesc` 가 **174자**, `_locales/en` 이 **242자**다.
크롬 매니페스트 참조가 `description` 을 "132자 이하" 로 못박고, 초과하면 심사가 아니라
**업로드 단계에서** `The description field in manifest is too long` 으로 거부된다.
`tools/validate.js` 의 20개 규칙 중 길이를 보는 것이 없다.

> 같은 문장에 F3(아래)이 겹쳐 있다. 어차피 다시 써야 하므로 한 번에 끝난다.

### B2. 스토어 스크린샷이 0장이다

크롬 웹스토어 등재는 **1280×800 스크린샷 최소 1장이 필수**다(스토어 아이콘과 함께, 이 둘만 필수).
저장소에 `icons/` 넷뿐이고 `store/`·`screenshots/`·`promo/` 가 없다.

### B3. 개인정보 처리방침이 없다

User Data FAQ 3·14가 **"로컬에만 저장하거나 `storage.sync` 만 써도 처리방침이 필요하다 — Yes"** 라고 명시한다.
그리고 FAQ 2는 "스크린샷 촬영" 과 "브라우저가 오가는 도메인 수집" 을 둘 다 user data 처리로 꼽는데,
이 확장은 **둘 다** 한다 — 공유 기능의 `captureVisibleTab`, 그리고 `crsStats.perOrigin` 이
방문 출처와 시각을 **기본값 켜짐으로 최대 200개** 보관한다(`settings-schema.json` 의 `collectLocalStats: true`).

기기를 안 떠난다는 것은 사실이고 그건 강점이다. 그러나 **공개 의무는 전송 여부와 무관하다.**

## 2. 가장 중요한 발견 열두 개

### F1. 타임어택 챌린지가 기본 설정에서 **항상 0점**으로 끝난다 — 심각도 상 · 비용 소

- `src/70-break.js:450` — 요소를 부술 때 점수는 `else if (state.combat)` 안에서만 오른다.
- `src/97-challenge.js:164` — 주석이 의도를 적어 뒀다: *"timeAttack and targetRush leave the mode alone"*.
- `settings-schema.json:1` — 기본 모드는 `rampage` 이고 거기서 `state.combat` 은 거짓이다.

그래서 명세가 "60초, **점수 최대화**" 라고 정의한 모드가 기본 경로에서 점수를 한 점도 못 쌓는다.

**대조군을 둔 재현** — 같은 페이지에서 같은 무기로 **똑같이 24개를 부쉈다**:

| 시작 모드 | `combat` | 부순 요소 | **점수** |
|---|---|---|---|
| `rampage` (기본값) | false | 24 | **0** |
| `survival` (대조군) | true | 24 | **504** |

`challenge.start('timeAttack')` 을 불러도 모드는 `rampage` 그대로였다.

**e2e 1256단언이 이 위를 그냥 지나간다.** 챌린지가 시작하는지, `reason === 'time'` 으로 끝나는지,
기록이 남는지는 보는데 **점수가 0이 아닌지는 아무도 안 본다.**

### F2. 테스트 1256단언 전부가 배포본에 없는 권한 위에서 돈다 — 심각도 상 · 비용 중

`test/e2e.js` 의 `prepareExtensionCopy()` 가 테스트 사본에만 넣는다:
```js
manifest.host_permissions = ['http://127.0.0.1/*'];   // ONLY in the test copy (activeTab needs a real gesture)
```
저장소를 그대로 올려 서비스워커로 토글하면 실제 사이트 여섯 곳 전부 `'blocked'` 를 돌려준다.
`host_permissions` 를 더한 사본으로 바꾸자 여섯 곳 전부 켜졌다.

주석이 이유를 정직하게 적어 뒀으니 속이려는 것이 아니다. 그래도 결과는 같다 —
`isInjectable()`·`looksBlocked()`·배지 수명·`tab.url` 이 비었을 때의 분기는 전부 **우리 코드**인데
사용자가 매번 타는 그 조건에서 자동 단언이 0개다. 12단계의 수동 검증이 단언 1256개가 못 본
결함 둘을 찾은 것은 우연이 아니라 이 구멍의 증상이다.

### F3. 공개 문구가 제품을 배신한다 — 심각도 상 · 비용 소

문서-구현 대조 **115항목 중 32항목이 어긋난다.** 특히:

| 어긋난 것 | 문서 | 실제 |
|---|---|---|
| 제품 소개 첫 문장 | `README.md:3` "웹페이지를 **유리판으로 바꿔서**" | 1단계가 폐기한 모델. `docs/specs/material.md:105` 가 "스토어 설명과 로케일에서 걷어낸다" 고 지시했다 |
| 스토어 짧은 설명 | `appDesc` "**열 가지 무기** / ten weapons" | 23종 + 사용자 정의 10 |
| `H` 키 | `README.md:51·148·218` "전투 ON/OFF" | `src/95-events.js:208` 모드 순환(램페이지→아케이드→서바이벌) |
| 무기 교체 딜레이 | `README.md` "250ms 고정" | `src/71-weapon-helpers.js:31` 110~560ms, 250은 폴백 |
| 프리셋 | 5종 | 9종 |
| README 가 아예 모르는 무기 | — | 샷건·못총·냉각총·중력탄·미니건 등 13종 |

12단계가 HUD 문구(`화면을 부수세요` → `요소를 부수세요`)를 고쳤는데 **같은 결함이 바깥에 그대로 남았다.**
명세의 완료 검사가 로케일만 봤기 때문이다.

### F4. 10단계의 아홉 기능이 기본 경로에서 하나도 안 보인다 — 심각도 상 · 비용 중

챌린지·인스펙터·공유는 `C`·`I`·`P` **키보드 전용**이고 HUD 버튼이 없다. README 에 등장 0회.
해금은 `unlockAll: true` 로 꺼져 있고, 누적 통계와 챌린지 기록은 옵션 페이지를 열어야만 보인다.
기획 레인이 센 바로는 기획 단위 36개 중 **16개(44%)가 사용자 요청 없이 추가**됐고
`docs/specs/product.md` 101줄에는 사용자 인용이 **0건**이다.

만든 것이 문제가 아니라, **만들고 안 보이게 둔 것**이 문제다.

### F5. 첫 세션에 안내가 하나도 없다 — 심각도 상 · 비용 소~중

`chrome.runtime.onInstalled` 핸들러가 없다. 설치 직후 아무 일도 안 일어난다.
온보딩 장치는 조작 안내 카드 하나뿐인데, `src/86-modes.js:168` 의 주석이 *"survival only, once per session"*
이라고 적어 둔 대로 **서바이벌에서만** 뜬다. 기본 모드는 램페이지다 — 그래서 **보통 사용자는 그 하나마저 영영 못 본다.**
글자 단축키 14개 + 숫자 10개 + `Shift+숫자` + 우클릭 + 꾹 누르기 + 드래그가 전부 README 에만 있고,
README 는 플레이 중에 아무도 안 본다. `?`·`F1` 도움말 키가 없다.

### F6. 첫 다섯 방이 "아무 일도 안 일어났다" 로 읽힌다 — 심각도 상 · 비용 소

네이버 첫 화면에서 기본 무기로 격자 39회를 7.8초간 클릭하며 10회마다 셌다.

| 클릭 | 경과 | 완전 파괴 | 부분 파괴 | 부서져 보이나 |
|---|---|---|---|---|
| 5 | 1.0초 | — | — | **아니다** |
| 10 | 1.9초 | 1 | 11 | 거의 아니다 |
| 20 | 4.0초 | 2 | 18 | 조금 |
| 39 | 7.8초 | 7 | 41 | **확실히** (상단 배너가 통째로 사라진다) |

파괴는 제대로 쌓인다 — 20~30클릭이면 보상이 온다. 문제는 **그 앞의 2초**다.
실제 웹페이지는 대부분 큰 컨테이너라 첫 다섯 방이 체력을 거의 못 깎는데,
안 죽은 요소의 피격 반응(흔들림·붉은 물듦)이 조용해서 **들어갔다는 사실 자체가 안 보인다.**
설치한 사람이 판단을 내리는 시간이 바로 그 2초다.

### F7. 밸런스 모델의 '핸들링' 축 절반이 플레이에 연결돼 있지 않다 — 심각도 상 · 비용 중

`src/71-weapon-helpers.js:15` 의 주석이 직접 적어 둔다:

> `moveSpeed    drone movement multiplier — NO drone avatar exists in this build, so it is carried and reported but not yet wired`

그런데 **바로 아홉 줄 아래**에서 같은 파일이 이렇게 말한다:

> `이 표의 swapMs 와 moveSpeed 가 §F 의 조정 대상이다. §F7 이 "피해량보다 핸들링(교체 · 이동 · 산포 · 재장전)을 먼저 건드린다" 고 했고…`

`moveSpeed` 를 읽는 곳은 `tools/balance.js`(`handling = moveSpeed × (1 − swapMs/2000)`),
무기 비교표(`src/68-interaction.js:648`), 사용자 정의 무기 기본값뿐이다. **플레이 코드는 한 곳도 안 읽는다.**

9단계가 "실전 11종 중 일곱이 밴드 밖" 을 고치면서 피해량은 §A2 가 못박아 못 움직이니 핸들링부터 움직였다.
그 핸들링의 절반이 **아무도 못 느끼는 숫자**다. 그리고 `--check` 가 CI 에서 그 숫자를 지킨다 —
되돌리면 CI 가 진다. 종이 위에서는 밴드가 맞고 손에서는 안 맞는 상태가 고정돼 있다.

**가장 싼 길**은 고치는 게 아니라 **인정하는 것**이다. `moveSpeed` 를 `handling` 공식에서 빼고
밴드를 다시 계산하면, 밸런스 표가 실제로 체감되는 값(`swapMs`·산포·재장전)만으로 서게 된다.
드론 아바타가 생기는 날 다시 넣으면 된다. 자세한 것은 [08-game-design.md](08-game-design.md).

### F8. 기본 무기 설정이 무기고의 절반도 모른다 — 심각도 중 · 비용 소

`settings-schema.json:3` 의 `defaultWeapon` enum 이 10종만 담고 있다(무기고는 23종).
**13종은 기본 무기로 지정할 수 없다.** `R10` 이 스키마의 내부 정합성은 검사하지만
enum 을 `WEAPON_IDS` 와 대조하지는 않는다. v1.3 의 10종 모델이 제품 안에 살아남은 자리다.

### F9. 램페이지에 끝이 없고, 챌린지 기록이 어디에도 안 보인다 — 심각도 중 · 비용 중

기본 모드에 종료 조건도 결과 요약도 없다. "잘 놀았다" 가 성립하지 않으면 다시 켤 이유도 안 생긴다.
챌린지 기록은 `crsStats.challenges` 에 저장되지만 옵션 페이지 일곱 섹션 어디에도 안 나오고,
결과 오버레이가 이전 최고 기록을 안 찍는다 — **2회차부터 피드백이 영구히 0이다.**

### F10. 데이터 사용 공개가 동작과 어긋난다 — 심각도 중 · 비용 소

옵션 페이지가 "아무것도 수집하지 않고 … 전부 이 브라우저 안에만 있습니다" 라고 말하는데,
`crsStats.perOrigin` 이 방문 출처를 기본값 켜짐으로 남기고 옵션 페이지가 상위 출처 표까지 보여 준다.
"네트워크 통신이 없다" 는 사실이고 "수집하지 않는다" 는 사실이 아니다.
**가장 싼 해결은 `perOrigin` 을 옵트인(기본 꺼짐)으로 바꿔 그 문장을 사실로 만드는 것이다** —
재미에 기여하는 바가 거의 없는데 공개 부담은 가장 크다.

### F11. 버그 리포트를 받아도 재현할 수 없다 — 심각도 중 · 비용 중

출시하면 "A 사이트에서 깨졌어요" 가 들어온다. 그때 쓸 것이 없다.

- 리플레이는 조작(`{t, op, args}`)만 담는다. **어느 URL 이었는지, 페이지가 어떤 모양이었는지가 없다.**
  좌표만으로는 남의 사이트에서 일어난 일을 되살릴 수 없다.
- 이슈 템플릿에 **사이트를 적는 칸이 없다.**
- 가장 흔한 결함(특정 사이트의 특정 레이아웃)이 정확히 재현 불가능한 범주다.

이 제품은 **임의의 웹페이지**가 입력이다. 입력을 못 받아 적으면 들어온 리포트의 대부분을 못 고친다.
리플레이에 `location.href` 와 간단한 DOM 지문을 더하고 이슈 템플릿에 사이트 칸을 넣는 것이 전부다.
자세한 것은 [07-sustainability.md](07-sustainability.md).

### F12. 릴리스를 실행해 놓고 태그를 안 붙였다 — 심각도 중 · 비용 소

`7a5dfa5` (2026-10-15, `chore(release): v2.0.0`) 가 릴리스 절차를 밟았는데 **태그가 0개**다.
그 뒤 **26커밋(11·12단계)이 CHANGELOG 를 한 줄도 안 건드렸고**, `[Unreleased]` 에는
2.0.0 보다 오래된 7단계 내용이 그대로 남아 있다. `README.md:40` 이 가리키는 Releases 페이지는 비어 있다.

기획 레인이 "1단계에서 출시했어야 했나" 를 따져 보고 **아니라고** 결론 냈다 —
실제 작업일은 6일이고 스토어 심사가 빌드보다 길다. 진짜 비용은 **10-15에 릴리스를 실행해 놓고
태그 하나를 안 붙인 채 20일을 보낸 것**이다.

## 3. 잘된 것

세 줄만 쓴다. 나머지 지면은 개선에 쓴다.

1. **가장 어려운 부분이 실제로 끝나 있다.** 실제 사이트 여섯 곳(위키백과·HN·GitHub·네이버·MDN·유튜브)에서
   주입 **32~71ms**, CSP·Trusted Types 위반 **0건**, Esc 뒤 `[data-crs]` **0개**.
   인라인 스타일을 전수 지문으로 떠서 대조하니 **값이 바뀐 것 0 · 새로 생긴 것 0 · 사라진 것 0**이다
   (GitHub `body` 의 22자는 GitHub 자기 것이었고 그대로 돌아왔다). "원래 값으로" 라는 약속이 적대적인 실제 페이지에서 성립한다.
2. **권한 셋뿐이라는 주장이 코드와 일치한다.** `chrome.*` 호출 전수 대조에서 초과가 없고 외부 네트워크 호출도 없다.
3. **회귀 방어가 이 규모의 개인 프로젝트에 흔치 않게 두껍다.** validate 20규칙 + `balance.js --check` 정적 파싱 +
   e2e 1256단언 + 생성물 `--check` 셋. F1·F2는 이 체계가 **무엇을 안 보는지**에 관한 지적이지
   체계가 부실하다는 뜻이 아니다.

## 4. 권장 순서

### 1주차 — 출시선 넘기 (전부 비용 소, 합쳐 2~3일)

1. **F1 타임어택 0점을 고친다.** 챌린지 중에는 점수가 오르게 하고, **그 단언을 e2e 에 박는다.**
   지금 이 버그가 서 있는 자리가 곧 테스트의 사각지대다.
2. **B1 + F3 를 한 번에.** `appDesc` 를 132자 안에서 다시 쓰면서 '유리판'·'열 가지'·'검' 을 걷어낸다.
   `validate.js` 에 **설명문 길이 규칙**과 **금지어 규칙**을 더해 다시 못 돌아오게 막는다.
3. **B3 처리방침** 한 장. 저장 키 전수표가 [05-trust-privacy.md](05-trust-privacy.md) 에 이미 있다.
   같이 **F10** — `collectLocalStats` 기본값을 꺼서 "수집하지 않는다" 를 사실로 만든다.
4. **F8 `defaultWeapon` enum** 을 23종으로. `R10` 에 `WEAPON_IDS` 대조를 더한다.
5. **F12 태그를 붙인다.** CHANGELOG 의 `[Unreleased]` 를 정리하고 11·12단계를 적는다.

### 2주차 — 사람이 쓸 수 있게 (비용 중)

6. **B2 스크린샷.** 이 검토가 실제 사이트에서 찍은 것들이 출발점이 된다.
7. **F5 첫 세션.** `onInstalled` 에서 한 번 열리는 안내, HUD 안의 `?` 도움말, 그리고 **F4** 챌린지·인스펙터·공유를
   HUD 버튼으로 끌어낸다. 이 셋이 같은 작업이다.
8. **F6 피격 반응 증폭.** 안 죽은 요소의 흔들림·물듦·피해 숫자 진폭만 올린다.
   체력도 밸런스도 안 건드리므로 `balance.js --check` 와 충돌하지 않는다.
   같은 결의 **비용 소** 짜리 조작감 수정 셋이 [08-game-design.md](08-game-design.md) 에 있다 —
   전역 쿨다운이 무기를 바꿔도 따라오는 것, 히트스톱이 *내가 맞을 때만* 걸리는 것
   (때릴 때 안 걸리면 타격이 가벼워진다), 난이도가 120초에 포화하는 것.

### 그 다음 — 구조 (비용 중~대)

9. **F2 스위트 E.** `host_permissions` 없는 사본으로 켜기·끄기·차단 페이지 **세 가지만** 검증한다.
   못 하면 못 한다고 `docs/specs/running-tests.md` 에 적고 수동 체크리스트 맨 위에 둔다. 지금은 둘 다 아니다.

### 끼워 넣을 것 — 전부 비용 소, 아무 때나

- **`CRS_LANES=1` 이 실제로는 안 돈다.** `CLAUDE.md:112` 와 `docs/specs/running-tests.md:56` 이

  부하가 높은 기기에서 쓰라고 적어 둔 탈출구가 바로 그 기기에서 못 쓰인다.
  `CRS_TIME_BUDGET_MS` 를 같이 올리라고 문서에 적거나, `CRS_LANES=1` 일 때 예산을 자동으로 늘린다.
- **CI 가 `docs/**` 를 건너뛴다**(`.github/workflows/ci.yml:13`). 그런데 `docs/BALANCE.md` 는 **생성물**이고
  `balance.js --check` 가 지킨다. 문서만 고친 커밋은 CI 를 안 돌리므로 **손으로 고친 생성물이 그대로 들어간다.**

## 5. 이 검토가 못 본 것

- **진짜 사람.** 전부 대리 평가다. 설치부터 5분까지 말하면서 플레이하는 사람 5~8명이 이 문서 전체보다 낫다.
- **전투 모드(아케이드·서바이벌)의 실제 플레이.** 실측은 램페이지 기본값만 했다.
- **느린 기기, 장시간 플레이의 성능 저하, 스크롤 중 동작.**
- **경쟁 제품의 실제 사용감.** 같은 틈새에 여러 확장이 있고(SuperSmashBrowser 는 별점 3.5에 평가 519개)
  그중 몇은 **이미 "요소 단위 파괴" 를 내세운다**(Break It, DOM Shooter, Break The Dom).
  "진짜 DOM" 만으로는 차별점이 약하다 — 깊이(23종·재질·전투·완전 복원·권한 셋)가 실제 차별점인지
  설치해서 비교해 봐야 안다.
- **모든 수치는 headless 1회 측정이다.** 주입 시간은 기기 부하를 탄다.
- **테스트 블록 시간 전부.** 실측한 것은 `ammo` 109초 · `rules` 77초 · `core` 69초 셋뿐이고
  나머지 다섯 블록은 주석값 추정이다. 큐 순서는 아직 맞다.

`dist/`. `node_modules/` 는 `.gitignore` 대상이라 추적되지 않으며, 실제 크롬 검증에 쓴 스크립트와
스크린샷은 저장소 밖 스크래치패드에 있다.

검토를 마친 시점의 저장소 상태: `node tools/build.js --check` 통과,
`node tools/validate.js` **19통과 · 1경고 · 0실패**.
