# 축 3 — 첫 세션 (설치 → 10초 → 5분)

## 요약 (3줄)
- 설치 직후 제품은 **아무것도 하지 않는다**(`onInstalled` 없음). 아이콘을 눌러 켠 뒤에도 HUD 힌트 한 줄 외에는 안내가 없고, 단축키 목록은 README 에만 있다(`?`/`F1` 없음).
- 질문 4 의 전제는 틀리다. **전투 모드는 기본 꺼짐**(`rampage`)이다. 오히려 README 가 "켜지면 전투 모드 토스트가 뜨고 5초 뒤 공격 시작"이라고 반대로 쓰고 있어, 문서가 실제 첫 경험과 어긋난다.
- 되돌릴 수 있다는 사실은 HUD 의 `↺ 복구`·`✕ 종료` 버튼으로 상시 노출되지만 "페이지가 진짜 안 망가진다"는 말은 제품 안 어디에도 없다. 차단 페이지는 1.5초 `✕` 배지가 전부다.

## 발견 (심각도 순)

### 1. 설치 직후와 아이콘 첫 클릭 사이에 안내 장치가 전혀 없다 — 심각도 상 · 비용 소
**증거**: `background.js` 에 `chrome.runtime.onInstalled` 없음(`grep -n onInstalled background.js src options` → 0건). 팝업 없음(`manifest.json` action 에 `default_popup` 없음), 환영 페이지 없음. 재현: 확장을 새로 로드 → 아무 변화 없음 → 아이콘은 퍼즐 메뉴 안.
**무엇이 문제인가**: 스토어에서 설치한 사람은 "설치됨" 토스트만 보고 끝난다. 아이콘을 핀 하지 않으면 보이지도 않고, 단축키 Cmd/Ctrl+Shift+X 는 어디에서도 알려지지 않는다. 클릭하면 팝업 없이 곧바로 켜지는 구조라, 클릭 전에 "무엇을 하는 물건인지" 정보를 얻을 곳이 스토어 설명뿐이다.
**재미 또는 출시 중 무엇을 해치는가**: 출시. 설치 후 이탈(설치만 하고 한 번도 안 켬)은 스토어 유지율·리뷰에 직결된다.
**제안**: `onInstalled`(reason==='install')에서 짧은 환영 페이지 1장을 연다 — 아이콘 핀 고정 방법, 단축키, "아무 웹페이지에서 켜고 클릭해 보세요", "Esc 로 끄면 원래대로". 새 페이지를 만들기 부담스러우면 기존 `options/options.html` 의 About 절 위에 첫 설치 배너를 얹어 그 페이지를 연다. 업데이트(`reason==='update'`)에서는 열지 않는다.
**반대 심문**: 환영 탭은 일부 사용자에게 스팸처럼 읽힌다. 다만 1회·`install` 한정이면 웹스토어 정책상 문제가 아니고(확인 필요: CWS 정책 문구), 기능 없는 확장을 하루 뒤 지우는 비용이 더 크다.

### 2. 단축키 24개 이상이 플레이 중 어디에서도 발견되지 않는다 — 심각도 상 · 비용 중
**증거**: 키 바인딩 전수는 `src/95-events.js:153-176` — 숫자 1~0, Shift+숫자, Q E R Z M H C I P, WASD/방향키/Space(서바이벌), Enter(KO·챌린지 결과), Shift 꾹, 우클릭. HUD 에서 키가 **눈에 보이는** 것은 슬롯 배지(1~0)와 재장전 프롬프트의 `R` 키캡뿐이다. M/Z/H/Esc 는 버튼 **툴팁**(`src/45-hud.js:243-247`, hover 해야 보임)에만, `C`(챌린지)·`I`(인스펙터)·`P`(공유)·`Q/E`·`Shift+숫자`·Enter 는 **README 에만** 있다. 도움말 키 없음: `grep -n "'?'\|F1\|Slash" src/95-events.js` → 0건. `docs/` 도 마찬가지(README:207-223 표).
**무엇이 문제인가**: 챌린지·인스펙터·결과 공유는 HUD 에 버튼이 없어 키를 아는 사람만 쓴다. 즉 제품의 차별 기능(챌린지 3종, 공유 이미지, 인스펙터)이 사실상 숨겨져 있다. 사용자가 플레이 중 확인할 곳이 없다.
**재미 또는 출시 중 무엇을 해치는가**: 둘 다. 재미: 5분 안에 챌린지·로드아웃 전환을 발견하지 못하면 "망치로 부수는 장난감"에서 끝난다. 출시: 스토어 설명에 적은 기능을 아무도 못 찾는다.
**제안**: (a) `?`(Shift+/) 또는 `F1` 로 키 카드 오버레이를 토글한다 — HUD 모듈에 조용히 추가, Esc 로 닫기, 입력창 포커스 시 무시. 내용은 이미 있는 `_locales` 키 + 짧은 한 줄씩. (b) HUD 에 `?` 아이콘 버튼을 하나 둔다(같은 오버레이를 연다). (c) 챌린지·공유는 HUD 아래 작은 한 줄 버튼으로 노출하는 것을 별도 검토.
**반대 심문**: HUD 는 이미 빽빽하다(5줄 + 힌트 + 상태). 버튼을 더하면 오히려 첫인상이 복잡해진다 → 그래서 제안은 `?` 하나뿐이고 나머지는 오버레이로 접는다. 또 단축키 다수가 "고급 사용자용"이면 발견되지 않아도 무방하다는 반론이 있으나, 챌린지/공유는 제품 핵심 가치라 해당하지 않는다.

### 3. 차단 페이지(chrome://, 웹스토어, file://, PDF)에서 아이콘을 누르면 이유를 알 방법이 없다 — 심각도 중 · 비용 소
**증거**: `background.js:44-54` `flashBlocked` — 배지 `✕`(빨강)를 1.5초 띄우고 지운다. 팝업·알림·`setTitle` 없음. 차단 목록 `background.js:9-14`. 주입 실패는 `looksBlocked`(`:35-38`)로 `blocked` 처리되어 같은 `✕`. 재현: 새 탭 페이지(chrome://newtab)에서 아이콘 클릭 → 1.5초 `✕`. 크롬 웹스토어 탭, `file://` 로컬 파일(파일 URL 접근 허용을 켜지 않은 경우)도 같다(확인 필요: file:// 실제 오류 문구와 `looksBlocked` 정규식 일치 여부).
**무엇이 문제인가**: 신규 사용자의 첫 클릭이 새 탭이나 스토어 설치 직후 화면(웹스토어)일 확률이 높다 — 설치한 바로 그 탭이 chrome 웹스토어다. `✕`는 "고장"으로 읽힌다. 1.5초라 놓치기도 쉽다. 시각 장애·스크린리더에게는 정보가 전혀 없다.
**재미 또는 출시 중 무엇을 해치는가**: 출시. "안 되는데요?" 1점 리뷰의 가장 흔한 원인이다. 이 확인되지 않은 첫 클릭이 사실상 거의 모든 신규 사용자에게 일어난다.
**제안**: 차단 시 `chrome.action.setTitle({tabId, title:'이 페이지에서는 쓸 수 없어요 — 다른 웹페이지에서 눌러 보세요'})` 로 툴팁을 바꾸고 배지는 유지 시간을 늘린다(예: 4초). 더 나은 방법: 차단 상태에서는 일회성 안내 페이지/`chrome.notifications` 는 권한이 늘어나므로 피하고, 대신 아이콘 `setTitle` + (제안 1 의 환영 페이지에 "웹스토어·새 탭에서는 안 돼요" 한 줄)으로 해결한다. 권한 추가 없이 가능하다.
**반대 심문**: 크롬이 이미 웹스토어·chrome:// 에서 확장이 동작하지 않는다는 것을 어느 정도 학습시켜 놨다는 주장. 그래도 `✕` 가 "이 확장이 설치 실패"로도 읽히는 것이 문제다. 또한 `setTitle` 은 호버해야 보이므로 단독으로는 약하다 → 환영 페이지와 같이 간다.

### 4. README 가 실제 첫 경험과 정반대로 서술한다 (전투 기본 켜짐처럼 쓰여 있음) — 심각도 중 · 비용 소
**증거**: `README.md:49-50` "켜지면 `⚔️ 전투 모드: …` 토스트가 뜨고 5초 뒤부터 큰 요소들이 공격을 시작합니다." 그러나 `settings-schema.json:2` 기본값 `rampage`, `src/20-state.js:31` `mode:'rampage'`, `src/86-modes.js:19`/`modeHasEnemies()` = `mode !== 'rampage'`. `src/99-api.js:195` 의 `toastCombatOn` 은 `activate()` 시점 `state.combat` 가 항상 false 라 죽은 분기다(저장된 모드는 `loadPrefs` 가 **silent** 로 나중에 적용해 토스트도, 서바이벌 안내 카드도 안 뜬다 — `src/99-api.js:~175`, `src/86-modes.js:139`). README:206 의 토스트 설명, README:219 `⚔️ 전투 ON / OFF` 도 HUD 현실(세 칸 `램페이지/아케이드/서바이벌`)과 다르다.
**무엇이 문제인가**: 질문 4 의 가정(기본 전투)은 틀렸고, 이건 좋은 설계다 — 조작을 모르는 사람이 5초 뒤 공격받지 않는다. 그런데 문서는 반대로 말해 스토어 설명·스크린샷·리뷰어 기대가 거짓이 된다. 부차적으로, 한 번 서바이벌을 골랐던 사용자는 이후 모든 페이지에서 토스트·안내 없이 곧바로 적이 나타난다.
**재미 또는 출시 중 무엇을 해치는가**: 출시(문서·스토어 문구 신뢰도). 재미에는 오히려 이득이다.
**제안**: README 사용법·HUD 표를 현실(기본 램페이지, `H` 는 램페이지→아케이드→서바이벌 순환)에 맞춘다. 죽은 `toastCombatOn` 분기는 별도로 정리하고, 저장된 전투 모드로 복원될 때 한 줄 토스트(`전투: 서바이벌 · 드론으로 피하며 쏘기`)를 띄울지 결정한다. 이 문서 수정은 축 1 문서 축과 겹칠 수 있으니 조율.
**반대 심문**: README 는 개발자 문서일 뿐 일반 사용자는 안 본다는 반론. 그러나 스토어 설명이 README 에서 파생되기 쉽고, 위 `toastCombatOn` 은 코드·i18n 에 살아 있어 의도도 불명확하다.

### 5. "되돌릴 수 있다"는 안심이 제품 안에 없다 — 심각도 중 · 비용 소
**증거**: 힌트 줄의 `복구(Z)로 되돌릴 수 있어요`(`_locales/ko` hudHintCollapse)는 붕괴 무기를 쓴 직후에만 뜬다(`src/76-weapon-fire.js:408`, `src/78-altfire.js:829`). `↺ 복구` 와 `✕ 종료` 버튼은 상시 있으나 클릭해도 확인 토스트가 없다(`src/99-api.js` restoreCore 에 `toast` 호출 없음, `grep toast( src/99-api.js` 는 `:195` 하나뿐). "복구하면 페이지는 원래대로 돌아오고, 새로고침해도 원래대로"라는 설명은 스토어 설명문(`appDesc` "모든 것은 복구할 수 있어요.")에만 한 번 있다.
**무엇이 문제인가**: 남의 페이지가 부서지는 것을 처음 보는 순간의 감정은 불안이다. 그 순간 화면 안에서 "이건 진짜 사이트를 바꾸지 않는다, 지금 Z/Esc/새로고침으로 되돌린다"고 말해 주는 곳이 없다. 버튼은 있으나 의미(`복구`가 무엇을 복구하는지)가 해석에 맡겨져 있다.
**재미 또는 출시 중 무엇을 해치는가**: 재미(불안한 채로는 과감하게 못 부순다). 출시(안전하다는 신뢰가 설치 결정의 핵심).
**제안**: 첫 활성화(저장 플래그 1회)에서 토스트 한 줄 — `Z 로 복구 · Esc 로 끝내면 원래대로 · 새로고침해도 원래대로`. 이미 `toast()`/`crsSeenCombatHelp` 와 같은 패턴(`chrome.storage.local`)이 있다. 복구 버튼을 눌렀을 때 "원래대로 돌렸어요" 토스트도 추가하면 클릭 피드백이 생긴다.
**반대 심문**: 실제로 새로고침하면 DOM 이 원래대로이므로 위험이 없고, `↺ 복구`·`✕ 종료` 라벨이 자명하다는 반론. 하지만 "새로고침해도 안전"을 아는 사람만 이 라벨이 자명하다. 또한 1.8초짜리 토스트에 담을 문장 길이를 실측해야 한다(확인 필요).

### 6. 첫 힌트 줄이 한 줄 안에 모순된 조작 두 개를 말한다 — 심각도 하 · 비용 소
**증거**: `src/45-hud.js:497-500` — 클릭 무기의 힌트는 `클릭해서 요소를 부수세요 · 길게 눌러 모으고 떼면 나가요`(hudHint + hudHintCharge). 기본 무기 망치에서도 그렇다. 기관총은 `꾹 눌러서 발사 · 짧게 누르면 다른 공격이 나가요`. "모으고 떼면 나가요" 가 무엇이 나가는지 말하지 않는다(`_locales/ko` hudHintCharge/hudHintBurst).
**무엇이 문제인가**: 첫 문장은 "클릭", 둘째 문장은 "길게 눌러라"로, 신규 사용자가 무엇을 해야 하는지 첫 5초에 헷갈린다. 알트파이어(차지) 문법은 숙련자용 정보다.
**재미 또는 출시 중 무엇을 해치는가**: 재미(첫 5분 이해도). 차지 샷을 못 발견하는 것은 덜 심각하다.
**제안**: 처음 N회(또는 첫 세션)는 `클릭해서 요소를 부수세요` 한 줄만 보이고, 차지 문장은 일정 클릭 수(예: 10회) 이후나 무기를 한 번 바꾼 뒤에 붙인다. 구현은 `updateHud` 의 한 분기.
**반대 심문**: 힌트가 길수록 많이 읽는 것은 아니고, 차지를 숨기면 발견 기회를 잃는다는 반론. 점진 공개로 풀린다.

### 7. 옵션 페이지에 도달하는 길이 크롬 기본 메뉴뿐이다 — 심각도 하 · 비용 소
**증거**: `grep -rn "openOptionsPage" background.js src options` 결과 0건, HUD·`background.js` 에 옵션 링크 없음(`src/45-hud.js` 전체에 `options` 문자열 없음). 아이콘 좌클릭은 토글이라 팝업이 없다. 도달 경로는 아이콘 우클릭 → `옵션`, 또는 `chrome://extensions` → 세부정보 → 확장 옵션 뿐(`manifest.json` `options_ui.open_in_tab`).
**무엇이 문제인가**: 옵션 페이지에는 무기고·통계·리플레이·사용자 지정 무기·접근성 설정(키보드 조준, 모션 줄이기)이 있다(`options/options.html` 섹션: 설정·무기고·표·통계·사용자 지정·리플레이·정보). 접근성 옵션까지 숨어 있어 필요한 사람이 못 찾는다.
**재미 또는 출시 중 무엇을 해치는가**: 재미(무기고·커스텀·통계 같은 장기 동기가 숨음), 출시(접근성 설정 발견성).
**제안**: 제안 2 의 `?` 도움말 오버레이 하단에 `설정 열기` 링크를 둔다. 콘텐츠 스크립트에는 `chrome.runtime.openOptionsPage` 가 없으므로 `chrome.runtime.sendMessage({type:'crash:options'})` → 서비스 워커가 `openOptionsPage()` 를 호출하는 메시지 하나를 `background.js` 에 추가한다(권한 추가 없음).
**반대 심문**: 우클릭 → 옵션은 크롬 표준 관행이라 학습된 경로라는 반론. 그러나 신규 사용자가 우클릭 메뉴를 열 이유가 없다.

## 확인 못 한 것
- 실제 크롬에 로드해 본 것이 아니다. 위 타임라인은 코드 추적이며, HUD 의 정확한 렌더(오른쪽 위 위치, 줄바꿈)는 `content.css:574` 와 CSS 로만 확인했다. 시각 검증 필요.
- `tab.url` 이 chrome://·웹스토어에서 `activeTab` 클릭 시 채워지는지(채워지면 `isInjectable` 로 단락, 아니면 주입 시도 후 `looksBlocked`). 두 경로 모두 `✕` 로 귀결되지만 오류 문구 정규식이 `file://`·PDF 뷰어(`chrome-extension://` 내부 문서 또는 `file://*.pdf`)에서 맞는지는 확인 필요.
- 웹스토어 정책상 `onInstalled` 환영 탭의 허용 여부 문구(일반적으로 허용되는 것으로 알려져 있으나 정책 원문 미확인).
- 스토어 설명문·스크린샷은 저장소에 없어(`docs/RELEASING.md` 는 배포 절차뿐) 스토어 목록이 README 의 어떤 문장을 인용하는지 알 수 없다.
- 영어 로케일(`_locales/en`)에서의 동일 키 상태는 읽지 않았다.
