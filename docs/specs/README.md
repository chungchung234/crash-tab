# 설계 명세

사용자 피드백에서 나온 변경을 구현 전에 글로 고정해 둔 문서들이다.
구현 에이전트가 읽는 1차 자료이므로 **반드시 버전 관리 안에 둔다.**

> 이 문서들은 원래 세션 스크래치패드(`/private/tmp/...`)에 있었고, macOS 의 임시 디렉터리
> 정리로 열흘 만에 전부 사라졌다. 작업이 한 번 막혔다. 수명이 긴 설계 문서는 임시 공간에
> 두지 않는다.

| 파일 | 로드맵 단계 | 상태 |
|---|---|---|
| `material.md` | 1 — 모델 교정 | ✅ 완료 |
| `settings.md` | 2 — 설정·성능·접근성 | ✅ 완료 |
| `test-speed.md` | 2.5 — 테스트 속도 | ✅ 완료 |
| `combat.md` | 3 — 전투 재구성 | 진행 중 |
| `crosshair.md` | 4 — 조준점·시각 정돈·뷰모델 | 대기 |
| `weapon-art.md` | 5 — 무기 아트 | ✅ 완료 |
| `destruction.md` | 6 — 무기별 파괴·타격점 파쇄·불 | 대기 |
| `arsenal.md` | 7~9 — 보조 사격·신무기·밸런스 | 대기 |
| `product.md` | 10 — 옵션·통계·도전·보스·공유 | 대기 |
| `running-tests.md` | — | 이 머신에서 테스트를 돌리는 규칙 |

로드맵 전체는 `../ROADMAP.md` 를, 작업 규칙은 저장소 루트의 `../../CLAUDE.md` 를 본다.

## 쓰는 법

- 구현 전에 해당 단계의 명세를 **끝까지** 읽는다.
- 명세에 없는 동작을 지어내지 않는다. 모호하면 고른 해석을 코드 주석과 보고에 남긴다.
- 명세가 틀렸다고 판단되면 코드를 명세에 맞추지 말고 **명세를 먼저 고친다.**
