# 모델 교정 — 화면이 아니라 "요소"를 부순다

로드맵 1단계. 다른 명세의 연출은 이 모델 위에서만 의미가 있으므로 가장 먼저 반영한다.
자국의 소유자와 좌표계에 한해 다른 모든 명세보다 우선한다.

사용자 지적: "이건 웹사이트 부수기인데 유리가 부셔지는 이펙트 때문에 스크린 부수기 같은 게
제일 어색한 것 같아. 스크린에 영향 있는 이펙트는 좋지만 기본적인 동작이 그게 되면 안 될 듯해"

---

## 1. 무엇이 잘못됐나

현재 균열은 `div.crs-canvas` — **뷰포트에 고정된 전체 화면 캔버스**에 그려진다.
즉 "화면 앞에 유리판이 한 장 있고 그걸 깬다"는 모델이다.

증상:
- 스크롤하면 균열이 화면에 붙어 따라온다. 페이지와 무관하게 존재한다.
- 요소 경계를 무시하고 균열이 화면을 가로지른다. 무엇을 때렸는지 알 수 없다.
- 조각도 `position: fixed` 라 스크롤하면 화면에 고정된다.
- 결과적으로 **모니터를 부순 것처럼** 보인다. 이 확장의 정체성은 웹사이트를 부수는 것이다.

v1 명세의 "웹페이지를 유리판처럼" 이라는 은유 자체가 틀렸다. 웹페이지는 유리판이 아니라
**물건들이 놓인 공간**이다.

## 2. 올바른 모델

> 웹 컴포넌트는 페이지에 박혀 있는 **물건**이다. 때리면 그 물건에 자국이 남고, 그 물건이
> 부서져 떨어진다. **화면은 절대 손상되지 않는다.**
> 화면 단위 효과(섬광·흔들림·비네트)는 손상이 아니라 **카메라 반응**이며 항상 일시적이다.

| | 영구적인가 | 좌표계 | 소유자 |
|---|---|---|---|
| 피해 자국(균열·탄흔·그을음·베인 자국) | 영구 | **요소 로컬** | 요소 |
| 조각 | 수명까지 | **문서** | 요소 |
| 섬광·충격파 링·화면 흔들림·비네트·히트스톱 | 일시 | 화면 | 카메라 |
| 조준점·HUD·오라·락온 | 상시 | 화면 | UI |

## 3. 자국을 요소로 옮긴다

- **전체 화면 캔버스(`.crs-canvas`)에 영구 자국을 그리지 않는다.** 이 캔버스는 제거한다.
  `src/25-layers.js` 의 `mk('canvas', 'crs-canvas')` 생성을 지우고, `src/30-canvas.js` 를
  데칼 렌더러로 재작성한다.
- 요소별 **데칼 캔버스**: `div.crs-decal[data-crs]` 안에 `<canvas>` 하나.
  - 요소 rect 크기 × DPR 로 만든다. CSS 크기는 rect 그대로.
  - glass root 에 올리고 `pointer-events: none`, `overflow: hidden` 으로 요소 경계에서 자른다.
  - 요소를 따라 움직인다. 적대 오라가 쓰는 **기존 one-shot RAF 추적**을 재사용한다.
    새 RAF 루프를 만들지 않는다. 스크롤·리사이즈·변위 모두 같은 경로로 처리된다.
  - 그리기는 **요소 로컬 좌표**로 한다. 타격점을 요소 rect 기준으로 환산해 넘긴다.
- `decalTargetAt(x, y)` — 뷰포트 좌표를 받아 `{ el, canvas, ctx, lx, ly }` 를 돌려준다.
  대상 요소가 없으면(최악의 경우에도 `body` 가 있으므로 실제로는 없지 않다) null.
  데칼이 없으면 그 자리에서 만든다.
- 어디를 때려도 대상 요소는 존재한다. 빈 배경을 때리면 그 자국은 배경 요소의 것이다.
- **폭발처럼 여러 요소에 걸치는 자국**은 영향받은 **각 요소의 데칼에 같은 폭발 자국을 각자의
  로컬 좌표로 나눠 그린다.** 결과적으로 그을음이 요소 경계에서 끊긴다 — 이게 맞다.
  "이 컴포넌트들이 그을렸다"로 읽힌다. 요소 사이 빈 공간에는 아무것도 남지 않는다.
- 상한 **40개**. 가장 오래전에 피해를 입은 것부터 200ms 페이드 후 제거한다.
  성능 모드에서는 12개.
- 해제: 요소가 부서질 때, `restore()`, `deactivate()`, 상한 퇴출.
  캔버스 참조를 끊어 detached canvas 가 남지 않게 한다.

## 4. 조각도 문서에 붙인다

- `debrisAnchor` 의 기본값을 `viewport` → **`document`** 로 바꾼다(옵션 자체는 유지).
- 조각은 스크롤과 함께 움직인다. 떨어진 자리에 남는다.
- 바닥은 뷰포트 하단이 아니라 **조각이 생성된 시점의 뷰포트 하단에 대응하는 문서 좌표**다.
  아래로 스크롤하면 위쪽에 쌓인 잔해가 화면 밖으로 올라간다. 정상이다.

## 5. 재질 — "전부 유리"를 버린다

요소 종류마다 부서지는 재질이 다르다. 이게 "웹사이트를 부순다"를 가장 직접적으로 만든다.

| 재질 | 해당 요소 | 자국 | 조각 | 소리 |
|---|---|---|---|---|
| **패널** (기본) | 배경이나 테두리가 있는 컨테이너, 카드, 섹션 | 각진 균열 + 가장자리 부스러짐, 무광 | 두껍고 각진 덩어리, 가장자리에 흰 단면 | 둔탁한 파쇄음 + 먼지 |
| **종이** | 텍스트 중심 요소, 문단, 제목, 목록 | 균열이 아니라 **찢어진 결**. 섬유가 일어남 | 단어·글자 조각이 팔랑이며 떨어짐(공기 저항 큼) | 찢어지는 소리 |
| **유리** | **이미지, 비디오, 캔버스, SVG** | **거미줄 균열** — 여기서만 쓴다 | 날카로운 파편, 반짝임 | 유리 깨지는 소리 |
| **플라스틱** | 버튼, 입력, 셀렉트, 배지, 칩 | 짧은 금과 흰 응력 자국 | 통째로 튕겨 나가거나 2~3조각, 탄성 있게 튐 | 딱 하고 꺾이는 소리 |
| **금속** | 구분선, 얇은 요소(짧은 변 12px 미만), 아이콘 | 움푹 패임, 긁힘 | 휘어진 조각, 한 번 더 튐 | 금속 울림 |

판정 함수 `materialOf(el)` — 순서대로 검사하고 첫 번째로 맞는 것을 쓴다:
1. `img, picture, video, canvas, svg` 또는 `background-image` 가 있는 요소 → `glass`
2. `button, input, select, textarea, [role=button], summary` → `plastic`
3. 짧은 변 12px 미만 또는 `hr` → `metal`
4. `textDominant(el)` 참 → `paper`
5. 그 외 → `panel`

**유리는 화면이 아니라 이미지와 비디오에만 남는다.** 화면처럼 생긴 요소가 유리처럼 깨지는 건
자연스럽다. 카드와 문단이 유리처럼 깨지는 게 어색했던 것이다.

무기별 파괴 프로필은 그대로 유지되고 **재질이 그 위에 곱해진다.**
예: 망치로 종이를 치면 쐐기 모양이되 찢어진 결과 팔랑이는 낙하가 적용된다.

## 6. 화면 단위로 남는 것

다음만 화면 좌표에 남고, 전부 **일시적**이다. 영구 자국은 하나도 없다.

- 섬광(`flash`), 충격파 링(`ring`), 화면 흔들림(`shake`), 피격 비네트, 히트스톱
- 조준점, HUD, 적대 오라, 락온 틀, 드론, 빔
- 폭발의 중심 섬광 — 단 그을음은 §3 대로 요소에 나눠 그린다

"스크린에 영향 있는 이펙트는 좋지만 기본 동작이 그게 되면 안 된다"를 그대로 따른다.

## 7. 문구 교정

- HUD 힌트, 스토어 설명, 로케일에서 **"유리판"** 은유를 전부 걷어낸다.
  (README.md 와 docs/ 는 오케스트레이터가 고치므로 건드리지 않는다.)
- 새 한 줄: `웹페이지의 요소를 하나씩 부숩니다` / `Smash a web page, one element at a time.`
- `appDesc` (ko): `웹페이지의 구성 요소를 직접 부숴 보세요. 때린 자리에 자국이 남고 조각이
  떨어져 쌓여요. 모든 것은 복구할 수 있어요.`
- 아이콘은 유지한다(깨진 유리 문양이지만 로고로서는 무방하다).

## 9. 테스트 (suite A)

1. `.crs-canvas` 가 존재하지 않는다. 타격 후 뷰포트 고정 좌표에 영구 자국이 없다.
2. 요소를 때린 뒤 **스크롤하면 자국이 요소와 함께 움직인다**(요소 rect 대비 자국 위치가 ±2px 유지).
3. 자국이 요소 경계를 넘지 않는다: 요소 바로 바깥 4px 지점의 픽셀 알파가 0 이다.
4. 조각이 문서에 붙는다: 조각 생성 후 300px 스크롤하면 조각의 뷰포트 top 이 −300px ±4 만큼 변한다.
5. 재질 판정: 이미지 → `glass`, 버튼 → `plastic`, 문단 → `paper`, `hr` → `metal`, 카드 → `panel`.
6. 유리 균열은 `glass` 재질에서만 생성된다. 카드를 때린 자국에 거미줄 폴리라인이 없다.
7. 종이 재질의 조각이 패널 재질의 조각보다 느리게 떨어진다(1초 후 낙하 거리 비교).
8. 폭발: 두 요소에 걸친 폭발의 그을음이 각 요소의 데칼에 나뉘어 있고, 두 요소 사이의 빈 공간에는
   자국이 없다.
9. 섬광·링·흔들림은 여전히 화면 좌표이며 1초 안에 모두 사라진다.
10. 로케일에 "유리판" 이 없다.
11. 복구(Z) 후 모든 데칼이 제거되고, 종료 후 `[data-crs]` 0개.
12. 성능: 데칼 40개가 떠 있는 상태에서 30회 타격 스트레스에 페이지 오류가 없고
    평균 틱이 8ms 를 넘지 않는다.
