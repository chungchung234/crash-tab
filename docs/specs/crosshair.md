# 조준점 고도화 · 시각 정돈 · 뷰모델 위치

로드맵 4단계. 3단계(전투 재구성)의 락온·적대 상태와 무기 스탯이 재료로 필요하다.

---

# A. 조준점

## A1. 지금의 문제

조준점이 **운영체제 커서 이미지**다(`cursor: url(hammer.svg) 6 6, crosshair`). 그래서:

- 애니메이션이 안 된다. 산포가 벌어져도, 쿨다운이 돌아도, 맞춰도 아무 변화가 없다.
- 무기가 10종인데 조준점은 하나다. 로켓의 폭발 반경도, 저격총의 정밀함도 보이지 않는다.
- 맞췄는지 빗나갔는지 조준점 근처에 신호가 없다. 시선은 조준점에 있는데 피드백은 멀리 있다.

운영체제 커서를 끄고(`cursor: none`) 직접 그린다.

## A2. 구조

`div.crs-crosshair[data-crs]` — glass root, 조준경 레이어 아래, `pointer-events: none`,
`will-change: transform`. 기존 tick 의 포인터 좌표를 받아 `translate3d` 로만 움직인다.
별도 RAF 루프를 만들지 않는다.

자식: `.crs-ch-arm` ×4, `.crs-ch-dot`, `.crs-ch-ring`(준비 상태), `.crs-ch-shape`(무기별 도형),
`.crs-ch-hit`(히트마커), `.crs-ch-hint`(관통·가려짐), `.crs-ch-hp`(체력 바, §B2).

**가시성 원칙**: 모든 선은 흰 채움 + 1px 검은 외곽(`drop-shadow`). 흰 페이지에서도 검은
페이지에서도 보여야 한다.

`cursor: none` 은 `html.crs-active` 에만 건다. HUD 위에서는 조준점을 숨기고 기본 커서를 되살린다.

## A3. 산포 연동 (핵심)

네 팔의 간격 `gap = 6 + spreadNow × 0.9` px. `spreadNow` 는 무기 기본 산포 + 반동 킥 + 블룸이다.

- 기관총을 연사하면 눈에 띄게 벌어지고 손을 떼면 0.4초 뒤 모인다.
- 저격총은 조준하면 `spreadNow = 0` 이라 완전히 모인다. 조준 중에는 조준경 화면이 대신하므로
  조준점 자체를 숨긴다.
- 서바이벌에서 드론이 움직이는 동안 `+4px`.

이 하나로 반동·블룸 스탯이 전부 눈에 보이게 된다.

## A4. 무기별 모양

| 무기 | 모양 |
|---|---|
| 권총 | 팔 4 + 중심 점, `armLen` 6 |
| 기관총 | 팔 4, 중심 점 없음, `armLen` 5 |
| 저격총 | 가는 십자 + 1px 점, `armLen` 10. 조준 시 숨김 |
| 망치 | 짧은 호 하나(휘두르는 궤적) |
| 도끼 | 굵고 긴 호 |
| 카타나 | 비스듬한 선분. 드래그 중에는 궤적 미리보기 |
| 폭탄 | 팔 4 + **점선 원**, 반지름 = 실제 폭발 반경 240px |
| 로켓 | 팔 4 + 점선 원 360px + 모서리 괄호 |
| 화염방사기 | 벌어진 원뿔 2선, 블룸에 따라 각도 변화 |
| 붕괴 | 큰 모서리 괄호 4개 |

폭탄·로켓의 반경 원은 `opacity: .35`. 커서를 따라다니므로 진하면 거슬린다.
**이 반지름은 충격파 링 최종 반지름, 그을음 가장자리와 같은 값이어야 한다**(6단계 폭발 교정).

## A5. 상태 색

| 상태 | 색 |
|---|---|
| 기본 / 부술 수 있는 요소 위 | 흰색 |
| 적대 요소 위 | `#e5484d` |
| 락온 중인 적 위 | 붉은색 + 0.25초 주기 맥동 (여기를 쏘면 끊긴다는 신호) |
| 부술 수 없는 곳(무적·HUD·빈 곳) | `rgba(255,255,255,.35)`, 중심 점 없음 |
| 쿨다운·재장전·교체 중 | 팔이 흐려지고 링이 돈다 |

## A6. 히트마커

사격이 피해를 입혔을 때 조준점 중앙에 짧게. 시선이 이미 거기 있으므로 가장 빠른 피드백이다.

| 결과 | 모양 | 색 | 시간 |
|---|---|---|---|
| 명중 | 대각선 4선(X) | 흰색 | 120ms |
| 치명타 | X + 바깥 테두리 | `#ffd166` | 160ms |
| 파괴 | X + 수축하는 원 | `#e5484d` | 200ms |
| 락온 차단 | 네 괄호가 바깥으로 튕김 | `#3fb950` | 240ms |
| 빗나감 | 표시 없음 | | |

연사 중에는 같은 노드를 재사용하고 애니메이션을 재시작한다.

## A7. 준비 상태 링

지름 26px, `conic-gradient` 로 진행도. 쿨다운은 0→1 로 채워지고, 재장전은 `#e3b341`,
교체는 흰색 40%. 대시 쿨다운(서바이벌)은 링 바깥의 작은 점.
탄약 HUD 를 안 봐도 언제 쏠 수 있는지 안다.

## A8. 깊이·관통 힌트

조준점 아래 10px:
- 커서 아래 요소가 적대 요소를 가리고 있고 관통이 없으면 `▼` 를 흐리게.
- 관통이 있으면 `▼` 를 밝게 + 층수.
- 폭발 무기면 범위가 엄폐를 무시하므로 표시하지 않는다.

## A9. 설정

`crosshair`: `auto`(무기별, 기본) / `cross` / `dot` / `circle` / `off`.
`crosshairColor`: `white`(기본) / `green` / `cyan` / `magenta`.
`crosshairScale`: 0.75 / 1 / 1.25 / 1.5.
`hitmarker`: bool, 기본 true. `crosshairSpread`: bool, 기본 true.
`showHpNumber`: bool, 기본 false.

`off` 면 운영체제 커서를 되살린다. 접근성과 취향 양쪽을 위해 필요하다.

# B. 시각 정돈 — 외곽선 줄이기

사용자: "타겟팅된 컴포넌트나 투사체의 외곽선은 오히려 집중을 방해하는듯해"

## B1. 원칙

화면에 같은 강도의 붉은 실선이 여럿 떠 있어 **무엇이 급한지 구별되지 않는다.**
가장 시끄러운 것이 가장 덜 중요한 것(단순 호버)이라는 게 특히 나쁘다.

**단단한 실선은 "지금 나를 해치려는 것"에만 쓴다.** 동시에 떠 있는 실선은 원칙적으로 하나다.

| 단계 | 표현 | 쓰는 곳 |
|---|---|---|
| 강 | 2px 실선 + 맥동 | 락온 진행 중, 돌진 예비, 레이저 고정 |
| 중 | 모서리 괄호 4개 | 현재 조준 대상 |
| 약 | 안쪽 그림자 + 작은 라벨 | 적대 요소의 평상시 |
| 없음 | 색·크기·밝기만 | 투사체, 일반 요소 |

## B2. 호버 타겟과 체력 바

- 전체를 두르는 2px 실선을 **없앤다.** 네 모서리에 10px 'ㄱ'자 괄호 4개만, 흰색 55%,
  바깥으로 2px. 배경 틴트도 없앤다.
- **체력 표시를 요소에서 떼어 조준점 아래로 옮기고 숫자를 없앤다.** 조준점 밑 14px, 가운데 정렬.
- **바의 가로 길이 자체가 최대 체력을 나타낸다:**

```
barW = clamp(round(20 + √maxHp × 6), 24, 140) px
```

| 대상 | 최대 체력 | 바 길이 |
|---|---|---|
| 단어 조각 | 19 | 46px |
| 버튼 | 44 | 60px |
| 작은 카드 | 99 | 80px |
| 큰 카드 | 184 | 101px |
| 큰 섹션 | 253 | 115px |
| 상한 | 400+ | 140px |

제곱근을 쓰는 이유: 최대 체력 자체가 면적의 제곱근에 비례하므로 바 길이가 결국 **요소의 한 변
길이에 대략 비례**한다. 큰 걸 겨누면 바도 길다는 직관이 맞는다.

- 높이 4px 고정, 채움은 `hp/max`. 색은 60% 초과 초록, 30% 초과 황색, 이하 붉은색.
- **상처가 없으면 조용하다**: `hp === max` 이면 불투명도 40%, 피해를 입으면 100%.
- 길이 변화에 전환 애니메이션을 주지 않는다. 대상을 옮길 때마다 늘었다 줄었다 하면 거슬린다.
- 이동할 때 괄호는 위치만 옮기고 다시 나타나는 애니메이션을 하지 않는다. 깜빡임이 피로의 원인이다.

## B3. 적대 요소 오라

- 평상시: **실선 테두리를 없앤다.** `box-shadow: inset 0 0 26px rgba(229,72,77,.30)` 과
  오른쪽 위 모서리의 작은 라벨만. 맥동도 없앤다.
  (전투 모드에서는 적만 유효 표적이므로 강도를 `.42` 로 올리고 라벨을 상시 표시한다.)
- **공격 준비에 들어갈 때만** 2px 실선과 맥동이 켜진다. 조용히 있다가 행동할 때 소리친다.
- 복구 빔을 쏘는 동안에도 켠다. 숨어서 일하는 건 막아야 할 일이다.
- 깊이 `back` 의 흐림은 유지하되 점선 테두리는 뺀다. 라벨의 `▲▲▲` 로 충분하다.

## B4. 설정

`targetMarker`: `brackets`(기본) / `full` / `off`.
`hostileMarker`: `quiet`(기본) / `always` / `off`.
`highContrastMarkers` 가 켜져 있으면 자동으로 `full` + `always` 로 올린다.

# C. 뷰모델 위치

사용자: "무기 위치가 너무 구석이라 안보여"

현재 `right: 8px; bottom: -8px` 에 200×100px. 1280×800 화면에서 세로 12% 다.
구석에 눌려 있고 아래가 잘려 무엇을 들고 있는지 보이지 않는다.

- 레이어를 뷰포트 비례로: `width = clamp(300, vw × 0.30, 520)`, `height = width × 0.56`.
  1280 폭이면 384×215 — 세로 24%, 일반적인 1인칭 시점 비중이다.
- 위치: `right: vw × 0.05`, `bottom: −height × 0.12`. 구석에 붙이지 않고 안쪽으로 들인다.
- `transform-origin` 을 `80% 100%` 로. 그림을 −8도 기울여 총구가 화면 안쪽 위를 향하게 한다.
- 창 크기가 바뀌면 다시 계산한다.
- `viewmodelScale`: 0.8 / 1(기본) / 1.3.

**탄약 HUD 와의 충돌**: 둘 다 우하단이다. 탄약 패널을 밀어 올리던 처리를 제거하고 `bottom: 24px`
로 되돌린 뒤, **뷰모델보다 위 레이어에 그린다.** 실제 FPS 가 하는 방식이다. 패널에 어두운
배경판이 있으므로 겹쳐도 읽힌다.

# D. 테스트

**조준점**: `cursor: none` 이 걸리고 `.crs-crosshair` 가 1개. 종료 후 둘 다 사라진다.
포인터를 따라온다(2프레임 내 ±2px). 기관총 15발 연사 중 팔 간격이 단조 증가하고 0.8초 쉬면
초기값으로. `crosshairSpread: false` 면 변하지 않는다. 10종의 `.crs-ch-shape` 구성이 다르고
폭탄·로켓의 점선 원 반지름이 각 무기 폭발 반경과 ±4px. 저격총 조준 시 숨고 해제 시 돌아온다.
적대 요소 위 붉은색, 락온 중 맥동, HUD 위 회색이며 기본 커서가 보인다.
히트마커 4종이 색으로 구분되고 `hitmarker: false` 면 생성되지 않는다.
로켓 발사 후 준비 링이 0→1 로 차고 쿨다운이 끝나면 사라진다. 재장전 중에는 색이 다르다.
가려진 적 위에서 권총이면 흐린 `▼`, 저격총이면 밝은 `▼2`, 로켓이면 표시 없음.
`crosshair: 'off'` 면 노드가 없고 `cursor` 가 `crosshair` 로 돌아온다.
`crosshairScale: 1.5` 면 팔 길이가 1.5배.

**시각 정돈**: 기본 설정에서 `.crs-target` 에 실선 `outline` 이 없고 모서리 괄호 4개가 있다.
체력 바가 `.crs-crosshair` 의 자손이고 기본값에서 숫자가 없다.
바 길이가 공식과 ±2px 이내이고 최대 체력 400+ 에서 140px 을 넘지 않는다.
상처 없는 대상에서 불투명도 0.4, 한 대 때린 뒤 1.0.
평상시 적대 요소의 `outline-width` 가 0 이고, 공격 준비가 시작되면 2px 가 되었다가 끝나면 0.
투사체 도착 링이 비행 60% 지점까지 없다. 맞을/빗나갈 궤적 불투명도 1.0/0.55.
`targetMarker: 'full'` 에서 실선이 돌아오고 `'off'` 면 노드가 없다.
`highContrastMarkers: true` 면 두 설정이 자동으로 올라간다.
일반 상황에서 동시에 존재하는 2px 실선 외곽선 노드가 1개 이하다.

**뷰모델**: 1280×900 에서 폭 384±8, 높이 215±6. 왼쪽 가장자리가 구석에 붙어 있지 않다.
그림의 바운딩 박스가 뷰포트 안에 70% 이상 들어온다. 640 폭에서 하한 300, 2400 폭에서 상한 520.
탄약 패널이 `bottom: 24px` 이고 뷰모델보다 z-index 가 높으며 겹쳐도 숫자가 읽힌다.
`viewmodelScale: 1.3` 이면 폭이 1.3배.

**무흔적**: 히트마커 애니메이션 중 `Escape` → `[data-crs]` 0개, 애니메이션 0개, 커서 복원.
**모션 축소**: 맥동과 히트마커 확대가 없고 색 변화만 남는다.
