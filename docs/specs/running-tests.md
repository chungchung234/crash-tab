# 이 머신에서 테스트를 돌리는 법 (반드시 지킬 것)

이 머신은 다른 작업으로 상시 부하가 높다(12코어에 평균 8~29). 백신이 CPU 의 40~50% 를
쓰고 있어 Chrome 이 임시 파일을 쓸 때마다 검사가 걸린다.

측정값:

| 명령 | 시간 | 내용 |
|---|---|---|
| 전체 (`node test/e2e.js`) | **71초** | 826 단언, 9개 레인, 동시 실행 4 |
| `CRS_BLOCKS=rules` | 57초 | 모드·적만 피해·적만 포커싱·아키타입·투사체 |
| `CRS_BLOCKS=core` | 56초 | 픽스처·주입·HP·무기 아트·재질·조준점·파괴 |
| `CRS_BLOCKS=ammo` | 42초 | 탄창·저격경·로드아웃·가독성 |
| `CRS_BLOCKS=combat` | 34초 | 드론·락온·복구 |
| `CRS_BLOCKS=debris` | 30초 | 파편 수명 |
| `CRS_BLOCKS=depth` | 28초 | 깊이·관통·변위 |
| `CRS_BLOCKS=settings` | 6초 | 스키마·성능 가드·접근성 |

레인이 슬롯보다 많으므로 **긴 레인을 먼저 큐에 넣는다.** 블록이 커지면 다시 재서
`A_BLOCKS` 순서를 고친다.

## 절대 규칙

**테스트나 빌드처럼 2분을 넘길 수 있는 명령은 반드시 `run_in_background: true` 로 돌린다.**
포그라운드로 돌리면 결과를 기다리는 동안 도구 호출이 멈추고, 180초 무진행이면 에이전트가
정지로 판정되어 죽는다. 이 세션에서 이미 다섯 번 그렇게 잃었다.

전체 실행이 86초가 된 지금은 포그라운드로도 한계 안에 들어오지만, 부하가 걸리면 두 배가
된다. 규칙은 그대로 둔다.

올바른 형태:

1. `node test/e2e.js > /tmp/<이름>.log 2>&1` 를 `run_in_background: true` 로 시작한다.
2. 출력 파일을 `until grep -q "SUMMARY" <파일>; do sleep 5; done` 으로 기다린다.
3. `SUMMARY:` 줄이 보이면 끝난 것이다.

## 반복 중에는 건드린 블록만

```
CRS_BLOCKS=settings node test/e2e.js
CRS_BLOCKS=core,ammo node test/e2e.js
```

블록은 일곱이다. 각각 자기 브라우저와 자기 페이지를 열고 자기 전제를 스스로 만들기 때문에
단독으로 돌아간다. 무엇이 어느 블록인지는 위 표에 있다.

**완료 판정은 항상 전체 실행이다.** 부분 실행은 요약에 `*** PARTIAL RUN ***` 을 찍고
총 실행 시간 단언을 건너뛴다. 모르는 블록 이름을 주면 즉시 종료한다.

`CRS_SUITES=A` (또는 B, C, D, E)로 스위트 단위로도 고를 수 있다. 블록 선택과 같이 쓸 수 있다.

## 스위트 E 와 자동화가 못 하는 것 (SPEC-launch §8)

스위트 A~D 는 `prepareExtensionCopy()` 가 **테스트 사본에만** 넣는 `host_permissions` 위에서 돈다.
`activeTab` 은 진짜 사용자 제스처(툴바 클릭 · `chrome.commands` 단축키)에만 주어지고 자동화는 그 길을
만들 수 없기 때문이다. 정직한 우회지만, 그래서 **사용자가 매번 타는 길에 오래도록 단언이 0개**였다.

**스위트 E 가 그 절반을 메운다.** 매니페스트를 손대지 않고 확장을 올려, 그 조건에서만 도는 코드를 본다 —
`isInjectable()` 의 URL 필터 12가지, 제스처 없이 부른 토글이 `'blocked'` 로 접히는 것,
배지 `✕` 가 1.5초 뒤 스스로 사라지는 것, 확장 페이지가 host 권한 없이 열리는 것. 4.5초면 끝난다.

**나머지 절반은 여전히 사람이 봐야 한다.** `activeTab` 이 부여된 **뒤**의 주입 성공 경로는 기계가 못 만든다.
아래 수동 체크리스트의 맨 위 항목이 그것이고, 스위트 E 의 마지막 `info` 줄이 그 사실을 실행 중에 다시 말한다.

- [ ] 실제 크롬에 압축 해제한 확장을 올리고 **툴바 아이콘을 눌러** 평범한 사이트에서 켜진다
- [ ] 단축키(`Ctrl/Cmd+Shift+X`)로도 켜진다
- [ ] `chrome://extensions` 에서 누르면 배지에 `✕` 가 잠깐 뜬다

## 동시 실행과 부하

네 블록과 스위트 B, C 가 각자 브라우저를 들고 동시에 돈다. `CRS_LANES` 가 동시 브라우저
수를 정하고 기본값은 `min(4, 코어 수 - 1)` 이다. 부하가 높아 아래의 가짜 실패가 나면
`CRS_LANES=1` 로 직렬화한다. **단 `CRS_TIME_BUDGET_MS` 를 같이 올려야 한다.**

```bash
CRS_LANES=1 CRS_TIME_BUDGET_MS=900000 node test/e2e.js
```

`CRS_LANES=1` 만 주면 완주하지 못한다. 워치독이 예산(`test/e2e.js` 의 `TIME_BUDGET_MS`, 기본 240초)에서
실행을 죽이고, 직렬에서는 블록 시간이 그대로 더해진다. 실측한 세 블록만 합쳐도 255초다
(`ammo` 109 · `rules` 77 · `core` 69). 나머지 다섯 블록과 스위트 B·C·D 가 아직 남아 있다.
그 상태로 끝나면 단언 실패가 아니라 `runtime budget exceeded` 가 보고된다.

## 시간 예산

기본값 240초는 레인 수가 기본값(병렬)일 때의 값이다. 직렬이거나 머신이 바쁘면
`CRS_TIME_BUDGET_MS=900000` 을 붙인다. 이 값은 워치독(예산 + 20초 뒤 강제 종료)과 테스트 안의
"총 실행 시간" 단언에 쓰이며 커밋하지 않는다. CI 는 병렬이라 `ci.yml` 에 240000 을 명시해 둔다.

## 죽은 실행이 Chrome 을 남긴다

예산 초과나 Ctrl-C 로 끊긴 실행은 브라우저를 닫지 못하고 **프로세스를 남긴다.** 한 실행이
레인마다 하나씩 열므로 열 개 단위로 쌓이고, 쌓이면 다음 실행이 느려져 또 끊긴다 —
스스로를 먹이는 고리다. 실제로 39개가 남아 있는 것을 발견했고, 그 상태에서 첫 실행이
240초 예산을 넘겼다.

```bash
pgrep -f "Chrome for Testing" | wc -l    # 실행 중이 아닐 때 0 이어야 한다
pkill -f "Chrome for Testing"            # 쌓였으면 정리한다
```

실행이 끝난 뒤 0 이 아니면 그 실행은 정상 종료한 게 아니다.

## 부하로 인한 가짜 실패

부하가 높을 때 다음이 간헐적으로 난다. 코드 회귀가 아니다. 한가할 때 다시 돌려 확인한다.
- `Attempted to use detached Frame` / `Target closed` — 프레임이 평가 도중 분리됨
- 물리 안정화를 기다리는 단언(파편 정지, 재낙하)이 경합에서 짐
- `total runtime < N s` 단언

같은 실패가 한가한 상태에서도 재현되어야 진짜 결함이다.
